# Contributing to AI Success Patterns

Thank you for contributing. This library is CC0 — everything here is public domain by design, and your contributions will be too.

---

## Ways to Contribute

### 1. Submit a New Pattern

Open a Pull Request adding a new file to the `/patterns/` directory. Use the naming convention `XX-pattern-slug.md` where `XX` is the next available number.

Your pattern must follow this structure:

```markdown
# Pattern Name

**Category:** Conversational | Agentic | Accuracy
**Status:** Draft | Community Review | Published

---

## Name
A memorable, action-oriented label (3–6 words)

## Context
The situation, role, or task type where this pattern applies.
One to three sentences.

## Problem
The specific failure mode, friction, or risk this pattern addresses.
What goes wrong when people don't use this pattern?

## Solution
The practice, framing, or structural approach.
Concrete enough to act on immediately.

## Value Consequence
What changes when you apply this pattern?
Observable outcomes, not aspirations.

---

## Notes
Optional: examples, variations, edge cases, related patterns.

## Source
Optional: where this pattern was first observed or described.
```

### 2. Improve an Existing Pattern

Submit a PR with your proposed edits and a brief explanation in the PR description.

### 3. Nominate a Backlog Pattern

Open an Issue with the label `backlog` and include:
- A proposed name
- One sentence on the problem it solves
- Where you've observed this pattern in the wild

### 4. Share an Example

Real-world examples make patterns stick. Open a PR or Issue linking to a public example (blog post, talk, LinkedIn post) of a pattern in action.

---

## What Makes a Good Pattern?

- **Grounded**: You've seen it work in practice, not just in theory
- **Portable**: It applies across tools, models, and contexts
- **Nameable**: It has a label that practitioners will immediately recognize
- **Consequential**: Skipping it has a visible cost

---

## Review Process

1. Open a PR
2. Community review (7 days)
3. Maintainer merge or feedback

All contributions are released under CC0. By submitting, you agree to dedicate your contribution to the public domain.

---

## Code of Conduct

Be specific. Be constructive. Cite examples. Disagree on ideas, not people.
