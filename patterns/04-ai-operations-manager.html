PATTERN 04 Agentic Practice

The AI Operations Manager

Define a recurring coordination role and assign it to AI as a persistent function - not a one-time task. The coordination tax on every knowledge worker's week drops substantially.

Problem

Coordination work drains the people who should be deciding

Professionals spend enormous time on coordination work: status updates, meeting prep, follow-up summaries, task routing, and information synthesis.

This work is necessary, predictable, and low-judgment - exactly the profile where humans are least valuable and most drained. Delegating it to AI as a one-off task captures some value. Delegating it as a structured, repeatable workflow captures far more.

Value

Attention shifts from managing information to using it

Less coordination overhead - the invisible tax on every knowledge worker's week. Asana found knowledge workers spend 58% of their day on "work about work": status, searching, and chasing (Anatomy of Work Index 2023)
Projects move faster not because the work is different, but because the friction between work and awareness is removed
The human's attention shifts from managing information to using it

Context

When this pattern applies

Multi-step workflows, project coordination, or any recurring process that involves organizing information, tracking status, routing tasks, or synthesizing inputs from multiple sources.

Applies when the work is structured but time-consuming - the kind of coordination work that rarely requires judgment but always requires attention.

Check first whether the coordination is the problem or a symptom. Status chasing often exists because the process is broken or handoffs don't work. Automating it can lock a bad process in place. Fix the stream first, then automate what's left (see Redesign the Stream, Not the Role, coming soon).

Solution

Assign AI a standing coordination role

Define a recurring coordination role and assign it to AI as a persistent function. Structure the AI's role with a standing context document (see Onboard, Don't Program) that describes the project, stakeholders, decision history, and current state. Treat each session as a handoff, not a cold start.

Chat sessions don't remember on their own, so give the standing context a home: a document the AI reads at the start of every session, or a project's knowledge files. Update it as decisions are made, so the next session starts from the current state.

Weekly

Synthesize project status from notes, emails, or tool exports; produce a briefing

Meeting Prep

Pull context from prior sessions; draft agenda and talking points

Post-Meeting

Capture decisions and action items in a structured format

Async Updates

Route information to the right summary document or channel

Cross-Project Risk

Flag risks and dependencies across projects, not just summarize each one's status

Notes

The entry point for most agentic deployments

This pattern is the entry point for most agentic AI deployments in professional services.

The pattern extends naturally into tool-connected agents (calendar, email, project management) when those integrations are available.

Decide where the freed time goes. This changes the coordinator's job; it shouldn't quietly erase it. Name the higher-value work the time moves to before you start (see Pattern 11, The Productivity-to-Headcount Trap).

At scale. Inside Anthropic, the share of employees’ AI sessions spent managing agents - writing instructions, building dashboards, monitoring pipelines - rose from 10% to 22% in about six months, and one engineer set up an “agent chief of staff” to triage agent requests (Wilmers, Catipon, Massenkoff and McCrory, “How Employment is Changing at Anthropic,” Anthropic, October 16, 2026). That is this pattern, run for real.

Give the role a handoff record. A standing AI coordinator is exactly the kind of asset that becomes a ghost when its owner leaves (see Pattern 12, Ghost in the Workflow).

Use this pattern

Paste this into any AI system's custom instructions or at the start of a conversation to run Pattern 04. It sets up an AI operations manager for your work: one dashboard where every agent reports its results, a simple way to add new agents, and the jobs it runs for you.

Pattern 04 - The AI Operations Manager 
# The AI Operations Manager

You are running Pattern 04: The AI Operations Manager from AI Success Patterns (aisuccesspatterns.com/patterns/04-ai-operations-manager.html).

The pattern's premise: coordination work - status, prep, follow-ups, routing, synthesis - is necessary, predictable and low-judgment, and it drains the people who should be deciding. Give it to an AI operations manager: a standing role that runs the recurring jobs, reports every result to one dashboard, and lets you add new agents as the work grows.

## Phase 1 - Check the process first
Ask the user, in one question, which project or workflow the operations manager will cover. Then ask whether the coordination is the problem or a symptom: does status chasing happen because handoffs are broken? If the process itself is broken, say so - automating it can lock it in - and suggest fixing the flow first (Pattern 21, Redesign the Stream, Not the Role).

## Phase 2 - Set up the dashboard
Agree on one dashboard where every result lands - a shared document, a spreadsheet, or a tracker page. Every run reports the same fields:
- Agent (which job ran)
- When it ran
- Status (done, failed, or needs a decision)
- What it produced, with a link
- The decision needed, if any
Show the user an empty dashboard with these columns. Results that aren't on the dashboard didn't happen.

## Phase 3 - Register the first agents
Offer these jobs and ask which to start with (one or two, not all):
- Weekly status briefing from notes, emails or tool exports
- Meeting prep: agenda and talking points from prior context
- Post-meeting capture: decisions and action items in a set format
- Overnight work runs (Pattern 15) - research, drafting, checking
- Cross-project risks and dependencies, not just status per project
For each one chosen, write a one-line registration: name, what it does, its inputs, when it runs, and who owns it. Keep the registrations as a list at the top of the dashboard.

## Phase 4 - Add an agent later
Explain how to add a new agent: write its one-line registration, add it to the list, and it reports to the dashboard with the same fields as every other agent. No new dashboard per agent.

## Phase 5 - Run the first one and review
Ask for the inputs for the first job, produce it, and write its dashboard row. Then ask what higher-value work the freed time will move to, so the role changes rather than quietly disappears (Pattern 11). Keep the registrations and standing context in a home outside the chat, so the next session picks up where this one left off.

## Behavior rules
- One question at a time
- Every result goes to the dashboard, with the same fields
- New agents get a registration before they run
- Don't invent status, dates or decisions - ask, or mark [Unconfirmed]
- Coordination only - decisions stay with the people

Works with Claude, ChatGPT, Gemini, Copilot, or any AI that accepts instructions.
