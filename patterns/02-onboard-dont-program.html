PATTERN 02 Agentic Foundation

Onboard, Don't Program

Treat AI like a new team member, not a search engine. The investment in context at the start pays forward across every interaction in the session.

Problem

Every interaction starts cold

Users treat AI like a search engine - one prompt, one answer, repeat. Each interaction starts cold. The model has no context about who you are, what you're building, what constraints you operate under, or how you make decisions.

Result: generic output, repeated corrections, and constant re-explanation of things that shouldn't need re-explaining.

Value

Output arrives already calibrated

The quality gap between "what AI produces" and "what I actually need" shrinks. Measure it: compare time spent correcting the first request in a session with the tenth.
Less time correcting; more time building
The investment in onboarding pays forward across every subsequent interaction in that session

Context

When this pattern applies

Extended AI-assisted work sessions where the model needs to understand your context, role, constraints, and preferences before producing useful output. Applies at the start of any project, engagement, or recurring workflow where the AI will be a consistent collaborator.

Solution

Open with a structured context document

Open extended AI sessions the way you'd onboard a new team member. Provide a structured context document at the start. Five things to include:

  • Who you areRole, industry, experience level
  • What you're working onProject, goal, current state
  • ConstraintsBudget, timeline, technology stack, regulatory environment
  • PreferencesCommunication style, level of detail, terminology
  • Decision criteriaWhat does "good" look like in your context
Example context document
  • Who I amEPMO director at a 4,000-person manufacturer; 15 years in portfolio management
  • What I'm working onA quarterly portfolio review for the executive team; Q3 data is in, the deck is not started
  • ConstraintsTen slides maximum; due Friday; financials stay at summary level
  • PreferencesPlain language, short sentences, no jargon; flag anything you're unsure of
  • Decision criteriaGood means an executive can decide which three projects to pause after one read

Share what the AI needs, within your organization's data rules. Rich context doesn't mean pasting confidential details into a tool that isn't approved for them.

Confirm understanding. Before it starts, ask the AI to restate the brief in its own words. A new hire's first check-in catches misunderstandings early; this does the same. Research on ambiguous requests found that resolving the ambiguity first generally improves the answer (Zhang and Choi, 2023).

This isn't programming or jailbreaking - and it isn't instead of clear instructions. Good onboarding includes them: context comes first, then the commands. The model produces work that fits your actual situation instead of a hypothetical average one.

Notes

Scales to teams

This pattern scales into persistent system prompts for teams and organizations. A shared onboarding document becomes a team's shared AI context - reducing variance in outputs and ensuring every team member's AI sessions start from the same foundation.

Even the AI vendors describe it this way: Anthropic's guidance tells users to treat the model as "a brilliant but new employee who lacks context on your norms and workflows."

Use this pattern

Paste this into any AI system's custom instructions or at the start of a conversation to run Pattern 02. It walks you through a short context document - who you are, what you're working on, your constraints, preferences and what good looks like - and has the AI play it back before any work starts.

Pattern 02 - Onboard, Don't Program 
# Onboard, Don't Program

You are running Pattern 02: Onboard, Don't Program from AI Success Patterns (aisuccesspatterns.com/patterns/02-onboard-dont-program.html).

The pattern's premise: treat AI like a new team member, not a search engine. A few minutes of context at the start pays off in every answer that follows.

## Phase 1 - Build the context document
Help the user write a short context document with five parts:
- Who they are - role, industry, experience
- What they're working on - project, goal, current state
- Constraints - budget, timeline, tools, rules they work under
- Preferences - communication style, level of detail, terms to use or avoid
- Decision criteria - what "good" looks like for this work

Ask about one part at a time, in that order. If the user has already covered a part, skip it. Keep each answer to a line or two. If they paste an existing context document, use it and only ask about what's missing.

Remind the user once, before Phase 1 starts: share only what their organization allows in this tool. Rich context doesn't mean confidential details in a tool that isn't approved for them.

## Phase 2 - Play it back
Restate the brief in your own words in five short lines, one per part. Name anything that seems unclear or contradictory, and ask about the most important one. Do not start the work until the user confirms the playback.

## Phase 3 - Start the work
Once confirmed, ask for the first task and do it. Use the context throughout the session without repeating it back. If something the user asks for conflicts with the context (a longer document than the constraint allows, a term they said to avoid), say so in one line before going ahead.

Offer once, at the end of Phase 2: "Want me to format this as a context document you can save and paste at the start of future sessions?"

## Behavior rules
- One question at a time
- Context first, then the commands - never start the task before the playback is confirmed
- Don't ask about parts the user already covered
- Flag conflicts with the context instead of quietly ignoring it

Works with Claude, ChatGPT, Gemini, Copilot, or any AI that accepts instructions.
